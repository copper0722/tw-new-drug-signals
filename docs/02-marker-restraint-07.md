# 02 — 訊號一：許可證上的 `07 新藥監視`

**這頁回答什麼**：怎麼從一張許可證直接看出它有沒有被列入新藥安全監視，
這個標記的意思到什麼程度為止，以及三個會讓比對器安靜出錯的地方。

端點與欄位在 [docs/00 §C](00-sources.md)，這裡不重複。

---

## 為什麼從這個訊號開始

因為它**不必等另外一則公告**。這個標記直接寫在許可證明細裡，查到證就查得到它。
訊號二（[docs/03](03-marker-nme-report.md)）中位落後 69 天（`M-14`），所以如果你要回答
「這個月核准了什麼」，訊號一是唯一來得及的。

**能講的到此為止。** 本 repo 沒有逐日追蹤過任何一張證的明細，所以說不出
「這個標記在核發當下就已經在了」——那需要在核發日與其後多次取樣同一張證，
本 repo 沒有做過。已知的只有：查詢當下它在明細裡，而且不需要等公告。

代價是它沒有官方定義文件，所以語意的界線只能用觀察去圍。下面圍給你看。

## 判定規則

`restraintItemsCode` 是字串陣列，每個元素是「碼 + 空白 + 名稱」：

```json
["02 輸 入", "07 新藥監視", "5E 已執行國內臨床試驗", "5F 免除銜接性試驗"]
```

規則只有一句：**取每個元素的第一個空白之前那段，判斷它是否等於 `07`。**

參考實作 [`reference/tw_restraint.py`](../reference/tw_restraint.py)：

```console
$ python3 reference/tw_restraint.py '02 輸 入' '07 新藥監視'
designated      True
matched_code    07
monitoring_family       07
interpretation  本 repo 解讀：…（完整字串見 tw_restraint.py）
```

第四行不是裝飾。`.interpretation` 會跟著判定結果一起旅行到下游報表，所以它自帶
「本 repo 解讀：」前綴——見本頁〈語意〉。

## 三個靜默陷阱

### (a) 比對碼，不要比對「監視」兩個字

限制項目碼表 91 筆裡（`M-03`），名稱含「監視」的有 **8 個**（`M-04`）：

| 碼 | 名稱 | 本 repo 對這個碼知道什麼 |
|---|---|---|
| `07` | 新藥監視 | ← 判定要的就是這一個碼 |
| `1K` | 安全監視 | 未量測 |
| `1L` | 監視中新藥 | 名稱含「新藥」；分布未量測 |
| `24` | 監視期滿學名藥 | 舊制「監視藥品之學名藥」分類，見下 |
| `25` | 監視中學名藥 | 同上 |
| `26` | 監視期滿新藥 | 名稱含「新藥」；分布未量測 |
| `27` | 監視中藥品 | 未量測 |
| `28` | 監視期滿藥品 | 未量測 |

用子字串「監視」比對，這 8 個全部判成 true——**而你的正控仍然會通過**，
因為帶 `07` 的真新藥的名稱裡也有「監視」兩個字。這是「只有正控的工具偵測不到
抓太多」的教科書案例（[docs/07 §1](07-controls-and-pitfalls.md)）。

這不是假想的風險。截至 **2026-08-05T14:47+08:00**，已取回明細的許可證裡
**至少有 7 張**帶 `24 監視期滿學名藥`（`M-48`）；子字串作法會把這 7 張全部
報成帶 `07`。

寫成「至少 7 張」而不是「7/356」是刻意的：明細是逐筆慢速取回的，母體隨時在
長——量測期間它就從 605 走到 623。**一個分母還在動的比率，寫下的當下就已經
過期了。** 這裡要證明的是「這件事真的會發生」，而存在性用下界表達不會失效：
下界只會變大。早期版本寫的「356 張裡 5 張」就是一次進行中作業的中途快照。

**注意「是不是新藥」這一欄本 repo 拿掉了。** 早期版本用它，於是隱含了兩個錯誤：
`1L 監視中新藥` 與 `26 監視期滿新藥` 的名稱裡明明有「新藥」，卻被留白；而
`24`／`25` 被寫成「學名藥自己在監視中」。`24`／`25` 實際上是舊制的
「**監視藥品之學名藥**」分類——它回答的是「申請這張學名藥時，該成分的第一張
**新藥**還在不在監視期內」，據以決定要檢附哪些臨床／BA-BE 資料，而不是宣告這張
學名藥自己落入新藥監視義務。法源與界線見
[docs/01 §3](01-what-counts-as-new.md)。

這對用途的影響是：`24`／`25` 仍然是「這張證不可能是該成分首見」的**強反指標**
（藥品查驗登記審查準則第 4 條定義學名藥為與國內已核准藥品同成分、同劑型、同劑量、
同療效），但本 repo **沒有**在母體規模上量測它們與其他碼的共現，所以它是反指標，
不是已證明的互斥。

### (b) 名字最像答案的欄位不是答案

回應裡有一個欄位就叫 `monitorDate`，中文是「監視期限」。它是**醫療器材**欄位，
在藥品上是 null。與監視期間有關的是 `validDate`（許可證有效期間），依據是
藥品安全監視管理辦法第 2 條——引文見 [docs/01 §3](01-what-counts-as-new.md)。

但 `validDate` 也不能直接讀成「還在監視期內」，因為許可證會展延。許可證效期的
法源是**藥事法第 47 條第 1 項**（不是監視辦法）：有效期間五年，每次展延不得超過
五年。兩筆實測（`M-49`，n = 2）：

| 許可證 | 發證日 | `validDate` | 差距 |
|---|---|---|---|
| 衛部菌疫輸字第001328號（2026 新分子） | 2026-06-25 | 2031-06-25 | 5 年，即第 47 條的原始效期 |
| 衛部藥輸字第026405號（2014 年核發） | 2014-10-23 | 2029-10-23 | **15 年** = 5 + 兩次展延，每次 5 年 |

n = 2。這兩筆說明「`validDate` 有時候不是那五年」，**不提供任何展延比例**。
第 47 條的展延上限剛好解釋第二筆為什麼是 15 而不是別的數字——法條與資料對得起來，
是一個弱但真實的佐證。

**別把兩個五年搞混**：藥事法第 47 條的五年是**許可證效期**；藥品安全監視管理
辦法第 8 條的五年是**定期報告義務**的期間，自發證日起算。監視辦法第 2 條又說
指定期間「以藥品許可證有效期間為準」，所以兩者在新證上重合，展延之後就不重合了。
條文引文見 [docs/01 §3](01-what-counts-as-new.md)。

也就是說：新證上 `validDate` 就是那五年；展延過的老證上它只是現行證期的終止日，
和新藥監視期已經無關。要直接回答「現在還在不在監視中」，碼表裡本來就有
`1L 監視中新藥` 與 `26 監視期滿新藥` 這兩個碼——**本 repo 沒有系統性量測它們的
分布**，所以這裡就只說到「有這兩個碼可用」為止，不給結論。

### (c) 別拿「監視成分」開放資料代替

見 [docs/01 §5](01-what-counts-as-new.md)。那是成分層級、供學名藥 BA/BE 用的
另一個概念，不是許可證層級的新藥清單。

## 語意：07 的觀察範圍

碼表只給名稱，不給定義。以下把**已查證的法源**、**已量測的事實**與
**本 repo 的讀法**分成三層，因為它們的可信度不同。

**法源**（逐字引文見 [docs/01 §3](01-what-counts-as-new.md)）：監視制度出自藥事法
第 45 條；藥品安全監視管理辦法第 8 條把新藥的定期報告義務綁在「本法第七條新藥」
的許可證上。**碼表本身沒有收錄準則，食藥署也沒有公開一份定義 `07` 的文件。**

**已量測的事實**（2026-08-05，逐筆走明細 API；末欄比對食藥署新成分新藥核准審查
報告摘要清單）。這七張都在 `M-44` 的 11 張裡，每一張都可以用
`python3 reference/tfda_lic_query.py <licId>` 自己再查一次：

| 許可證 | 是什麼 | 帶 07？ | 在新成分新藥清單上？ |
|---|---|---|---|
| 衛部菌疫輸字第001328號 | 佐加洛注射劑（IBALIZUMAB），2026 新分子 | 是 | 是（2026-07-24 公告） |
| 衛署藥製字第033862號 | METRONIDAZOLE 學名藥 | **否**（只有 `01 國 產`） | 未公告 |
| 衛部藥輸字第029062號 | 耐脂德膜衣錠（Nustendi），ezetimibe + bempedoic acid，**兩個成分都不是第一次出現在許可證上** | 是 | 未公告 |
| 衛部菌疫輸字第001082號 | 杜避炎注射劑 300 毫克（dupilumab） | 是 | **是**（2018-12-05 公告） |
| 衛部藥輸字第028546號 | 康紓維 42 毫克，成分是 leuprolide **mesylate**（既有品項為 acetate） | 是 | **是**（2023-12-05 公告） |
| 衛部菌疫輸字第001230號 | 四價流感疫苗年度換株 | 是 | 是（2023-04-20 公告） |
| 衛部藥輸字第026405號 | 恩排糖膜衣錠 25 毫克（empagliflozin），**2014-10-23** 發證 | 是（`M-50`；查詢日距發證日 11 年 9 個月） | 未公告 |

「未公告」只代表這張證的號碼不在該清單上，**不代表食藥署認為它不是新成分新藥**
——那份清單的沉默沒有否定的意思，理由見 [docs/03](03-marker-nme-report.md)。

**本 repo 的讀法**，只走得到這裡：

1. `07` 標示這張證被列入藥事法第 45 條的上市後安全監視。
2. 觀察到的範圍：它出現在食藥署自己公告的新成分新藥證上，**也**出現在成分並非
   首次出現於許可證上的證上（029062 的兩個成分都已核准多年）。所以相對於自算的
   moiety 首見訊號，`07` 看到的範圍比較寬。
3. **推不出集合關係。** 早期版本寫「`07` 是『新成分』的超集」，那是一個數學敘述，
   而支撐它需要 `07` 的收錄準則（未公開）加上母體普查（本 repo 只逐筆查過少量
   許可證）。兩樣都沒有，所以那句話已刪除，不要再寫回來。
4. 同樣推不出法定分類：**帶 `07` 不等於這張證被審查認定為第 7 條某一款新藥**，
   反向也不成立。第 7 條的身分來自審查認定，不是來自一個限制項目碼。

**不可以寫的兩句話：「07 = 新成分新藥」、「07 是新成分的超集」。** 任何形式都不行。

### 它不是「現在還在監視期內」

那張 2014 年的 empagliflozin 證（衛部藥輸字第026405號），2026-08-05 查詢時仍然
帶 `07`（`M-50`，n = 1）。所以 `07` 至少不是現行監視狀態的即時反映——要回答
「現在還在不在監視期內」，可用欄位與其限制見陷阱 (b)。

**能講的只有這樣。** 早期版本把它寫成「永久戳記」，那需要追蹤同一張證在監視期
前後的明細變化，本 repo **沒有做過**這種縱向量測。一張 2014 年核發的證在 2026 年
的一次查詢裡還帶著它，是一個時點觀察，不是一條規則。（早期版本這裡寫「12 年前的
證」——那是一個會自己過期而且進位進錯邊的裸數字：查詢日距發證日是 11 年 9 個月。
把日期寫出來，讀者自己算得出來，而且明年不會變成假的。）

## 成本

每張證一次 POST。本 repo 逐筆引用的 11 張（`M-44`）以 30 秒間隔取得，未觸發
限流；422 的意義見 [docs/00 §C](00-sources.md)。

這個成本結構決定了用法：**它適合驗證一份候選清單，不適合掃描全部 66,440 張證**
（`M-05`）。候選清單從哪來，就是訊號二和訊號三的工作。

## 怎麼確認我沒搞錯

| 檢查 | 正控（必須亮） | 負控（必須不亮） |
|---|---|---|
| 比對器抓對碼 | `["02 輸 入","07 新藥監視"]` → true | `["25 監視中學名藥"]` → false；`["24 監視期滿學名藥"]` → false |
| 沒有退化成子字串比對 | 上面的正控 | 把整個陣列當成一個字串傳進去時，工具要**報錯**而不是照做 |
| 資料真的取到了 | `60001328` 回傳陣列含 07 | `01033862` 回傳 `["01 國 產"]`，長度 1 |
| 沒有把限流當資料 | — | 422 時不得寫入「無此標記」 |
| 語意沒有被放大 | 寫「觀察到 `07` 出現在哪些證上」 | 寫「`07` 是新成分的超集」「`07` 是永久戳記」 |

負控刻意取自**最容易被誤判為正**的那一族：`24`／`25` 這兩個名稱含「監視」又含
「學名藥」的碼，不是隨便一個不相干的碼。理由見
[docs/07 §1](07-controls-and-pitfalls.md)。

這些控制在 [`reference/tests/test_restraint.py`](../reference/tests/test_restraint.py)
裡是可執行的，其中 `test_substring_match_would_have_passed_the_positive_control`
同時斷言「正確作法判 false」與「錯誤作法會判 true」。

### 過期偵測

如果 `60001328` 有一天不再回傳 `07`，代表上游語意變了，本 repo 的結論就過期了。
那是本 repo 的活體 canary，指令見 [Makefile](../Makefile) 的 `check-live`。
