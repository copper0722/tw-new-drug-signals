# 07 — 驗證協議：怎麼知道自己沒搞錯

**這頁回答什麼**：前面各頁的陷阱收斂成一份可執行的檢查表，以及三個在把數字
寫出去之前一定要做的檢查。

---

## 1. 每個工具需要兩個控制

**正控只能證明工具會叫。只有負控能抓到工具叫太多。**

一個把所有東西都判成 true 的比對器，正控會完美通過。所以「我測過了，正控有亮」
這句話，對「有沒有多抓」這個問題完全沒有資訊量。

而且**負控要取自最容易被誤判為正的那一族**，不是隨便一個明顯不相干的樣本。
一個本來就不可能匹配的負控，什麼也證明不了。本 repo 的三組負控都是這樣挑的：

| 工具 | 正控 | 負控（同族、易混） |
|---|---|---|
| `07` 判定 | 帶 `07 新藥監視` 的 IBALIZUMAB 證 | `24 監視期滿學名藥`／`25 監視中學名藥`——名稱裡也有「監視」 |
| moiety 首見 | `DASATINIB`（2008 首見證） | `DASATINIB MONOHYDRATE`（2026，同分子的水合物寫法） |
| 標題解析 | 一般單證公告 | 短尾範圍、公司名黏字別、R 序號、來源錯字 |

負控的身分**只對那個比對器成立**。`24`／`25`／`26` 是「EXACT-`07` 比對器」的
負控，不是「這些藥不是新藥」的判斷——`26` 的名稱就叫「監視期滿新藥」。把工具的
負控讀成對世界的分類，是本頁 §3 (b) 那個病的另一種形式。

全部在 [`reference/tests/`](../reference/tests/) 裡可執行，
共用的具名對照組在 [`fixtures/controls.json`](../fixtures/controls.json)。

## 2. 檢查表

跑完這 **15** 項再對外講話（`M-51`；訊號一 5 項、訊號二 5 項、訊號三 5 項）。
每一項都寫成「必須成立 / 必須不成立」的形式。

引言裡的項數早期版本寫 12，清單實際有 14。現在這個數字是**數出來的**，而且有
測試釘住（`test_runnable_measurement_matches_the_register`）：往清單加一項而沒改
引言，`make test` 會紅。一個要靠人記得同步的計數，遲早會不同步——訊號三加入
「成分欄是現況值」那一項時，這個測試當場就把還寫著 14 的引言擋下來了。

### 訊號一（`07`）

- [ ] 比對的是**碼** `07`，不是子字串「監視」。負控：`25 監視中學名藥` 判 false。
- [ ] 沒有把 `monitorDate` 當成監視期限（那是醫材欄位，藥品為 null）。
- [ ] 沒有把 `422` 記錄成「無此標記」。
- [ ] 任何寫出去的句子裡，`07` 不等於「新成分新藥」，也沒有主張兩者的集合關係
      （超集／子集）。負控：出現「超集」兩個字。
- [ ] 沒有把「帶 `07`」寫成「經審查認定為第 7 條新藥」。

### 訊號二（新成分新藥清單）

- [ ] 範圍與列舉標題有展開。負控：只取每則第一張證，你會少 24.5% 的證（`M-19`）。
- [ ] 字別取自 61 筆封閉集合、用最長匹配。負控：貪婪中文字元類會在 20 則上抓錯（`M-22`）。
- [ ] R 開頭序號沒被 `[0-9]` 錨點濾掉（`M-23`）。
- [ ] 展開後的候選，**每一張都在許可證資料裡查得到**（`M-12`）；查不到的不收。
- [ ] 沒有把「清單上沒有」讀成「不是新藥」。

### 訊號三（moiety 首見）

- [ ] 基線涵蓋全部許可證，**含已註銷**（`M-05`）。負控：REMDESIVIR 2023 那張判為非首見。
- [ ] 鹽別／賦形劑清單是封閉的這件事有寫在輸出旁邊，不是只寫在程式碼註解裡。
- [ ] 成分資料缺漏的列有現形，沒有靜默消失（`M-31`）。
- [ ] 完整年度的逐年計數落在 31–50（`M-34`）；**部分年度不適用**這個檢查。
- [ ] 知道成分欄是**現況值**，不是核發當時的快照（`M-54`）。負控：把「發證日 +
      今天的成分欄」當成這張證核發時的成分。

## 3. 三個要在數字寫出去之前做的檢查

下面三條是本 repo 在這份資料上被抓到過的三種錯，收斂成可以直接執行的動作。
逐筆的案例留在它們發生的那一頁，這裡不重述。

### (a) 親手打開你最高風險的那一筆命中，再報數字

判準太寬的比對器，正控會完美通過，然後你會拿著一個看起來很漂亮的計數去報告。
唯一擋得住的動作是：**在報出數字之前，把清單裡風險最高的那一筆親手打開來看。**
那是一次檔案讀取或一次查詢，而它常常是唯一擋下誤告的東西。

### (b) 一句蓋住 N 筆的概括，要有 N 筆的證據

概括不會停在原地，它會長出解釋。本 repo 曾用一句話蓋住七筆不一致（「都是同一個
分子的第二張證」），接著據以替它們指定施行細則第 2 條的款別，再把那個讀法寫進
法規那一頁——而七筆裡有兩筆根本不是那回事，一筆是鹽別被正規化剝掉，一筆是排序
用錯了日期欄位（[docs/05](05-crosswalk.md)）。**概括寫得越順口，越少人會回頭
逐筆檢查**，而逐筆檢查正是這個 repo 對外主張的方法。

同一個病的另一種形式在 §1：把「這是 EXACT-`07` 比對器的負控」讀成
「所以這些藥不是新藥」。工具的負控是關於工具的敘述，不是對世界的分類。

### (c) 自己組出來的數字，回頭直接查一次它本身

差值、比值、代理指標——凡是用兩個真數字組出來的，那個組合本身通常沒有人觀察過，
而且過程中不會有任何一步報錯。兩個實例都在本 repo 裡：一個減錯了東西的差值
（`M-38`，[docs/05](05-crosswalk.md)），以及兩個對目標根本沒有辨別力的代理指標
（`M-43`，[docs/06](06-permit-identity-and-dates.md)）。

做法只有一個：**把那個數字本身當成一次查詢送出去。** 順帶一提，這一條也適用於
比值的另一邊——量了分子沒量分母，等於只做了一半。

## 4. 太乾淨的結果是缺陷報告

如果你的比對器在一份雜亂的真實資料上得到 100% 覆蓋、零例外，那是關於**工具**
的假說，不是關於**資料**的假說。

本 repo 的數字裡沒有一個是 100%，除了兩個——而那兩個的可信度**完全不同**：

- 發證日覆蓋率 19,705 / 19,705（`M-08`，母體 `M-06`）：它是清單的**篩選條件之一**，所以必然
  是 100%。這是套套邏輯，資訊量為零，留著只是為了跟核准日的 1.5% 對照。
- 公告展開後 273 / 273 存在於許可證資料（`M-12`）：這是一個**外部**檢定（拿自己
  的解析結果去對一份不是自己產生的資料），所以它是有意義的 100%。

差別值得記住：前者不可能不是 100%，後者可能不是而剛好是。**只有後者是證據。**

## 5. 活體 canary

本 repo 的結論綁在上游語意上。如果哪天：

- `60001328` 不再回傳 `07 新藥監視`，或
- `Lic.Type` 不再是 61 筆（`M-01`）、`Restraint.Dr` 不再是 91 筆（`M-03`）、
  或其中「監視」不再是 8 個（`M-04`），

就代表上游變了，本 repo 過期。指令：

```bash
make check-live      # 一次請求，打已知正控
make measurements    # 離線，重跑所有算得出來的數字
```

兩者分工清楚：`check-live` 問「上游還是不是我以為的樣子」，`measurements` 問
「我寫下的數字和我隨附的檔案還對不對得起來」。後者完全離線。

`make check-live` 刻意**不進任何自動化測試**：`make test` 完全離線，不對政府主機
發出任何請求。canary 是人在想起來的時候手動跑的。

**422 不算 canary 失敗**——那是我方被限流，見 [docs/00 §C](00-sources.md)。
這件事寫在文件裡不夠，工具本身要分得出來，所以 `check-live` 的作業分成三種結果：

| 結果 | 印出來的 | 作業本身的退出碼 |
|---|---|---|
| 問到了，`07` 還在 | 那個限制項目陣列 | 0 |
| 問到了，`07` **不在了** ← 只有這個是 canary 失敗 | 陣列裡沒有 `07` | 1 |
| **沒問到**（HTTP 錯誤／逾時／422） | `# 查詢失敗…那不是 canary 失敗` | 3 |

**但 `make` 會把所有失敗都收斂成 exit 2**，不管作業本身回幾。所以透過
`make check-live` 跑的時候，**要看訊息，不要看退出碼**——分辨「標記不見了」和
「我方被限流」的是那兩行輸出。要拿退出碼做判斷，就把 Makefile 裡那段 curl 與
python 直接拿去用（實測：作業回 1／3，`make` 兩種都回 2）。

早期版本用裸 `curl -s`，於是 422 的錯誤頁被送進解析器、印出 `None`、退出 1——
同時犯了本 repo 自己禁止的兩件事：把限流寫成「標記消失」，以及把限流報成
canary 失敗。**一份寫著這條規則的文件，配一個違反它的工具**，是這裡最容易發生
也最難自己看見的一種錯。

## 怎麼確認我沒搞錯

| 檢查 | 正控（必須成立） | 負控（必須不成立） |
|---|---|---|
| 你真的有負控 | 每個工具都能講出一個「必須不亮」的具名樣本 | 只講得出正控 |
| 負控挑得夠近 | 負控來自最易混淆的同族 | 負控是一個本來就不可能匹配的樣本 |
| 負控沒有被讀成分類 | 「這是 EXACT-`07` 比對器的負控」 | 「所以這些藥不是新藥」 |
| 概括有逐筆證據 | 一句蓋 N 筆的話，N 筆都打開過 | 打開三筆，概括七筆 |
| 控制不會在健康資料上亮紅燈 | 逐年計數的檢查排除了部分年度（`M-34`） | 2026 的 26 被當成異常 |
| 離線測試真的離線 | `make test` 不需要網路 | 測試在斷網時失敗 |
| 數字都登記過 | 每個數字都有 `M-NN`，查得到母體、方法與重跑方式 | 一個講不出母體的數字 |
| 複合數字被查過 | 差值／比值本身有直接觀察過 | 只驗了兩個原料就相信結果 |
| 重跑指令真的能跑 | 貼上去就會執行 | 引用一個從未定義的變數，貼上去拿到 `NameError` |
