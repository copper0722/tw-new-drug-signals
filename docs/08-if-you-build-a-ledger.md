# 08 — 如果你要做一份持續更新的清單

**這頁回答什麼**：把三個訊號變成一個「每週告訴我新增了什麼」的東西時，
會踩到的那個結構性問題，以及一個不依賴任何特定基礎設施的解法。

這頁不談資料庫廠牌、不談排程器、不談主機。

---

## 問題：上游沒有 diff

許可證資料是**整表重載**的。每次更新拿到的是一份完整快照，不是異動清單。
所以「這週新增了什麼」這個問題，**資料本身回答不了**。

### 尾隨時間窗是錯的解法

最直覺的作法是「取發證日在最近 N 天內的證」。它會漏掉東西，而且漏得很安靜。
三件事各自都足以讓它失效：

**一、資料本身就落後。** 2026-08-05 量測（`M-45`）：整份資料裡最新的發證日是
2026-07-16，現行製劑・菌疫子集則是 2026-07-07——也就是落後 20 到 29 天。一個
七天的窗，在資料還沒追上來之前就已經是空的。（這個落後天數每天都在動，引用時
要帶量測日；早期版本寫「將近三週」，那是前一天的說法而且偏低。）

**二、真正的新品項本來就稀疏。** 2025-01 至 2026-06 的 78 個完整週裡，有 32 週
（**41%**）沒有任何 moiety 首見旗標（`M-46`）。所以「這週是零」是常態，不是訊號
——你無法從零裡分辨「這週沒有新藥」和「我的窗漏了」。

早期版本在這裡寫的是「搭配每月 15–34 張的節奏，一個七天的窗會在多數週得到零」。
**那句話兩邊都不對**：「每月 15–34 張」用任何一個想得到的分母都重現不出來（每月
首見旗標中位數是 5、範圍 1–20；每月全部新發證中位數是 26、範圍 14–54），形狀最
接近的其實是逐年公告則數 15–32（`M-16`）——一個把「每年」讀成「每月」的錯位；
而「多數週」也是誇大，實際是 41%。已刪除，換成上面那個直接量到的週零率。

**三、最致命的是公告落差。** [docs/03](03-marker-nme-report.md) 的中位落差是 69 天
（`M-14`）——公告可以晚上好幾週甚至好幾個月，而那時它的發證日早就滑出你的窗外了。

用時間窗，你會安靜地漏掉**每一個晚公告的品項**，而漏掉的東西不會留下痕跡。

## 解法：逐筆首次觀察，只回報一次

不要問「這一批和上一批差在哪」，改成問「這一筆我以前見過嗎」。

- 每次重載後，逐筆比對你自己的清單。**沒見過的就記一筆首次觀察。**
- 每一筆只回報一次，回報後標記已回報。
- 回報時帶的是它**真正的發證日**，不是你觀察到它的日期。

這樣一來，一個晚了三個月才出現的品項，仍然會在它出現的那一週被回報，
而且帶著正確的日期。時間窗做不到這件事，因為它問的是錯的問題。

### 一張證一列，一個訊號一筆證據

本 repo 不出 schema（理由見 README〈刻意不做〉），但形狀有一個地方非講不可，
因為它是這整頁的重點：**訊號不能存成證上的一個欄位。**

三個訊號的到達時間不同：`07` 不必等另一則公告，新成分新藥公告中位晚 69 天
（`M-14`）。所以同一張證會先以 `07` 進來，幾個月後才被公告確認——那是**同一筆
的補強**，不是新的一筆，也**不是把前一個訊號覆蓋掉**。一個 `marker_source`
文字欄位會讓第二個訊號抹掉第一個，而抹掉之後沒有任何欄位會抗議：你會失去
「這張證最早是被哪個訊號看見的」，而那正是這份清單唯一能講的事。

所以最小的形狀是兩層：

- **每張證一列**：許可證號、真正的發證日（見 [docs/06](06-permit-identity-and-dates.md)）、
  第一次在快照裡看到它的日期、是否已回報。
- **每個訊號一筆證據**，掛在那張證底下：哪個訊號、什麼時候確認的、
  依據是什麼（公告網址、明細查詢日）。同一張證可以有三筆，也可以只有一筆。

回報時取的是這些證據裡**最早**那一筆的時間，而不是最新那一筆。

## 兩條會省下麻煩的規則

### 1. 無法分類的列必須現形

成分欄為空、或正規化後不剩任何 moiety 的證，要以「**成分資料缺漏**」出現在
報表上，不能靜默丟棄。

**消失的列和不存在的列長得一模一樣。** 真實資料裡有 140 張現行證的成分欄是空的
（多為醫用氣體之類），另外 16 張的字串正規化後不剩東西，合計 156 張（`M-31`）。
它們不是零，它們是「不知道」。

### 2. 改了判定演算法，就要把最後一份輸出跑出來看

改對了資料、改對了回填、控制也重新驗過，這些都在管線的**前端**。一條管線是在
它最後一個介面上被驗證的：把報表真的跑出來，確認印出來的數字跟著變了。讀取端
沒改到的話，前面全部通過，而它照樣供應被取代的舊值——包括報表自己那段
「本清單如何判定新藥」的說明文字，那段敘述也是一個讀者。

## 一份清單該長什麼樣

如果這份清單要給人看（尤其是掛在真名底下），至少要標示：

- 每一筆是**哪個訊號**判定的，以及那個訊號的意思（連到 [docs/05](05-crosswalk.md) 的決策表）。
- 日期是**發證日**，不是核准日，也不是你觀察到的日期。
- 「本清單沒有」不等於「不是新藥」——尤其當你的判定依賴中位落後 69 天的來源時（`M-14`）。
- 成分資料缺漏的筆數（`M-31`）。
- 每一個對外的數字，量測日期與母體。本 repo 自己的做法是一個
  [`measurements.json`](../measurements.json)：文件引用編號，編號那裡寫著母體、
  方法、重跑指令，以及引用時必須一起講的話。

最後把三個訊號各自的身分講死，因為它們**不是同一種東西**，寫成一句「都是候選
產生器」會低估其中一個、高估另外兩個：

| 訊號 | 它是什麼 | 它不是什麼 |
|---|---|---|
| 新成分新藥核准審查報告摘要 | **它列出來的每一筆都是權威**——食藥署自己審查認定並公告的新成分新藥，清單上的正面事實可以直接引用 | 它的**沉默**不可用：不在上面推不出「不是新藥」（[docs/03](03-marker-nme-report.md)） |
| `07 新藥監視` | 一個可以直接讀到的事實：**這張證的明細裡有 `07` 這個碼** | 不是法定身分的判準。食藥署未公開收錄準則，帶 `07` 不等於經審查認定為藥事法第 7 條新藥 |
| moiety 首見 | **純粹的候選產生器**，本 repo 自己算的字串首見 | 沒有任何官方地位；已知有偽陽性，1,218 張旗標從未被外部確認（`M-38`） |

要發表的清單，不一致的地方要逐筆打開，像 [docs/05](05-crosswalk.md) 那樣。

## 怎麼確認我沒搞錯

| 檢查 | 正控（必須成立） | 負控（必須不成立） |
|---|---|---|
| 不是用時間窗 | 一個發證日在三個月前、這週才首次出現的品項，會被回報 | 它因為滑出窗外而消失 |
| 只回報一次 | 同一張證跑兩輪重載，只出現一次 | 每次重載都重報 |
| 日期是發證日 | 回報帶的是它真正的發證日 | 帶的是觀察日 |
| 訊號沒有互相覆蓋 | 一張先被 `07` 看見、幾個月後才被公告確認的證，兩筆證據都還在 | 第二個訊號蓋掉第一個，最早的觀察時間消失 |
| 缺漏有現形 | 報表上有「成分資料缺漏 N 筆」 | 報表加總 < 母體，而且沒有解釋 |
| 讀寫兩端一致 | 改判定演算法後，跑一次**完整報表**確認數字變了 | 只驗前端，沒跑最後一份輸出 |
| 訊號身分沒有被拉平 | 公告清單的正面事實可以直接引用 | 一句「三個都是候選產生器」把公告清單也降級 |
